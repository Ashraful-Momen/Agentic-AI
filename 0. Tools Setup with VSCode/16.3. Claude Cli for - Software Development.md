# 🛡️ Claude CLI Development Guild — Team Reference

> **এই ডকুমেন্ট যার জন্য:** পুরো টিম — যে কেউ Claude Code (CLI) ব্যবহার করে যেকোনো প্রজেক্টে কাজ করবে।
> **যে কাজে:** নতুন প্রজেক্ট শুরু, প্রজেক্ট চালানো, ডেলিভারি, দলের সাথে হ্যান্ডঅফ।
> **নীতি:** প্রতিটা প্রজেক্টে একই structure, একই pattern, একই slash command discipline — যাতে যে কেউ যেকোনো প্রজেক্ট ধরলেই ৫ মিনিটে চিনে যায়।

## ⚡ Quickstart — নতুন প্রজেক্টের প্রথম ৩০ মিনিট

পয়েন্ট ফর্মে step-by-step:

- **[ ] ১. প্রজেক্ট ফোল্ডারে terminal open করুন** — VS Code / Cursor / যেকোনো editor-এ ওপেন করুন
- **[ ] ২. Claude Code চালু করুন** — টার্মিনালে `claude` টাইপ করুন
- **[ ] ৩. প্রথম কমান্ড** (একবারই):
  ```
  /init
  ```
  Claude পুরো প্রজেক্ট স্ক্যান করে একটা `CLAUDE.md` বানাবে।

- **[ ] ৪. Personal + project memory সেট করুন** (একবার):
  ```
  /memory
  ```
  এই command মেমোরি ফাইল খুলবে। আপনার preferences যোগ করুন।

- **[ ] ৫. Project structure রেকর্ড করুন** — `/init` যা বানায় তা পর্যালোচনা করুন এবং প্রয়োজনে edit করুন
- **[ ] ৬. PROGRESS.md + TODO.md ম্যানুয়ালি তৈরি করুন** (Claude Code auto বানায় না)
- **[ ] ৭. প্রতিটা সেশনের শুরুতে**:
  ```
  CLAUDE.md, PROGRESS.md, TODO.md পড়ে বলো কোথায় আছি
  ```
- **[ ] ৮. কাজ চলাকালীন** → `/goal`, `/iteration` pattern ব্যবহার করুন (নিচে details)
- **[ ] ৯. সেশন শেষে** → PROGRESS.md আপডেট + নতুন learning → `/memory` তে save
- **[ ] ১০. Context বড় হলে** → `/compact`

## 📁 Part 1: ফাইল ম্যাপ — কোথায় কী থাকবে (Universal)

নিচের structure **যেকোনো** প্রজেক্টে একই রকম। Tech stack বদলাক না কেন, এই জায়গাগুলো একই থাকবে:

```
<your-project-name>/                          ← প্রজেক্ট রুট
│
├── CLAUDE.md                                  ← 🆕 প্রজেক্ট DNA (Claude /init দিয়ে বানায়)
├── PROGRESS.md                                ← 🆕 কী শেষ, কী চলছে
├── TODO.md                                    ← 🆕 পরবর্তী কাজের লিস্ট
├── README.md                                  ← প্রজেক্টের public ডকুমেন্টেশন
├── claude-cli_development_guild.md            ← (এই ফাইল — রেফারেন্স, বাংলা)
├── claude-cli_development_guild_en.md         ← (এই ফাইল — রেফারেন্স, English)
│
├── src/   অথবা   client/, server/             ← আসল কোড
├── tests/                                      ← টেস্ট
├── docs/                                       ← বিস্তারিত ডকুমেন্টেশন
│
│   (CLAUDE.md subfolder এও রাখা যায় — monorepo তে ভালো কাজে দেয়)
│
└── .claude/
    └── settings.json                          ← Hooks (PostToolUse ইত্যাদি)
```

> ⚠️ **Claude Code-এ কোনো auto-managed memory নেই** — z-code যেমন `~/.zcode/cli/memories/...` রাখে, Claude Code-এ **memos আপনাকে স্পষ্টভাবে save করতে হয়** `/memory` কমান্ড দিয়ে।

### Claude CLI Home Directory

```
~/.claude/                                       ← user-level config
│
├── CLAUDE.md                                    ← 🔑 GLOBAL memory (সব প্রজেক্টে auto-load)
│                                                ← /memory কমান্ড এটাই খোলে
│
└── settings.json                                ← user-level hooks/permissions
```

**CLAUDE.md এর hierarchy (উপরের সব সময় নিচেরকে override করে):**

```
১. ~/.claude/CLAUDE.md          ← user-level (সব প্রজেক্টে applicable)
২. <project>/CLAUDE.md         ← project-level (শুধু ওই প্রজেক্টে)
৩. <project>/<subfolder>/CLAUDE.md ← subdir-level (শুধু ওই folder এর কাজে)
```

## 📝 Part 2: প্রতিটা ফাইলের বিস্তারিত

### 2.1 `CLAUDE.md` — প্রজেক্টের DNA

**তৈরি করার উপায়:**

```
/init
```

Claude পুরো code-base স্ক্যান করে একটা comprehensive `CLAUDE.md` বানায়। আপনি review + edit করে নিন।

**Claude যা যা রাখে (সাধারণত):**

```markdown
# CLAUDE.md

## Project Overview
<প্রজেক্ট কী, কেন তৈরি হয়েছে, কার জন্য>

## Architecture
<stack, folder structure, key patterns>

## Key Files
<গুরুত্বপূর্ণ ফাইল/ডিরেক্টরি>

## Commands
<build, test, lint, dev commands>

## Conventions
<naming, formatting, git workflow>

## Domain Context
<business rules, glossary>
```

**সেরা আউটপুটের জন্য কাস্টমাইজ করুন:**

```markdown
# CLAUDE.md — <Project Name>

## Identity
- নাম: <project name>
- ধরন: <web app, CLI, mobile, ERP, ...>
- Stack: <React + Node, vanilla JS, ...>

## Folder Structure (গুরুত্বপূর্ণগুলো)
- /src → মূল কোড
- /tests → টেস্ট
- /docs → ডকুমেন্টেশন

## Conventions
- Naming: <PascalCase | kebab-case>
- Indent: <2 spaces | 4 spaces>
- Commit: <conventional commits>

## Do NOT touch (যদি কোনো volo/team member code ভালো থাকে)
- <file path>
- কারণ: <reason>

## Run / Build / Test
- Develop: <npm run dev>
- Build: <npm run build>
- Test: <npm test>

## Verification
- <manual | automated | lighthouse>
```

**কখন update করবেন:** নতুন feature, stack change, বা team member যোগ/বাদ গেলে।

> 💡 **Pro tip:** `/init` চালানোর পর CLAUDE.md পড়ুন। যা ভুল বা অসম্পূর্ণ সেটা নিজে edit করুন — Claude পরবর্তী session এ সেটা পড়বে।

### 2.2 `PROGRESS.md` — কী শেষ, কী চলছে

**⚠️ Claude Code এটা auto তৈরি করে না** — আপনাকে নিজে বানাতে হবে।

**টেমপ্লেট:**

```markdown
# Progress Log — <Project Name>

> Last updated: <YYYY-MM-DD>

## ✅ Done
- [YYYY-MM-DD] <feature> — <file paths>
- [YYYY-MM-DD] <bug fix>   — <issue/ticket id>

## 🚧 In Progress
- <feature> — <file> (status: X% complete)

## 🔜 Up Next (TODO.md থেকে নামবে)
- <next feature>

## 📝 Decisions / Notes
- [YYYY-MM-DD] <decision>: <why>
```

**আপডেট discipline:**

| Trigger | Action |
|---|---|
| ফিচার শেষ | "PROGRESS.md তে Done entry add করো" বলুন |
| Sub-task শেষ | শেষ এ update করুন |
| সেশন শেষ | অবশ্যই ১ মিনিট দিয়ে update করুন |

> **Claude Code-এ auto-update নেই।** Hook দিয়ে customize করা যায় (Part 6 দেখুন)।

### 2.3 `TODO.md` — পরবর্তী কাজের লিস্ট

**⚠️ এটাও manual তৈরি** করতে হবে।

**টেমপ্লেট:**

```markdown
# TODO — <Project Name>

## 🔴 High priority
- [ ] <task> — <reference>
- [ ] <task>

## 🟡 Medium priority
- [ ] <task>

## 🟢 Low priority / Polish
- [ ] <task>

## ✅ Recently completed (শেষ ৫টা, archive বাকিটা)
- [x] <old task>
```

**Claude এর TodoWrite tool vs TODO.md:**

Claude Code-এ built-in `TodoWrite` tool আছে — এটা **transient** (শুধু এই session এ) কাজের লিস্ট রাখে। কিন্তু **persistent tracking এর জন্য TODO.md এখনো সবচেয়ে ভালো**, কারণ:
- Across sessions টিকে থাকে
- Team দেখতে পারে
- Git এ commit হয়

**মিক্স strategy:** Claude-কে বলুন "TodoWrite দিয়ে ৩টা sub-task track করো + শেষে TODO.md update করো"।

### 2.4 Memory (~/.claude/CLAUDE.md) — আপনার global memory

**এটা Claude Code-এর persistent memory** — `/memory` কমান্ড দিয়ে edit হয়।

**Claude Code-এ দুই ধরনের memory:**

| Type | Location | কী থাকে |
|---|---|---|
| **Project memory** | `<project>/CLAUDE.md` | ওই প্রজেক্টের rules, conventions |
| **User memory** | `~/.claude/CLAUDE.md` | আপনার global preferences (যেকোনো প্রজেক্টে applicable) |

**`/memory` কী করে:**

```
/memory   →   opens user memory file (~/.claude/CLAUDE.md) 
             for editing in $EDITOR

/select-memory   (কিছু ক্ষেত্রে) — choose which memory file to edit
```

**Example user memory entries:**

```markdown
# ~/.claude/CLAUDE.md

## User preferences
- আমি Banglish এ কথা বলি
- Detailed plan আগে চাই, তারপর কোড
- বাংলা কমেন্ট কোডে রাখি

## Coding style
- TypeScript > JavaScript
- সবসময় error handling সহ function
- console.log debug এ ব্যবহার করি না

## Workflow
- PROGRESS.md + TODO.md দিয়ে track রাখি
- কোনো project এ session শুরুতে এই ৩টা পড়ি
- হেভি কাজে GOAL pattern use করি
```

**কখন save করবেন:**

| Trigger | কখন save করবেন |
|---|---|
| নতুন preference বললেন | সাথে সাথে `/memory` |
| প্রজেক্ট শুরুতে | `/memory` (user) + `/init` (project) |
| Weekly review | শুক্রবার `/memory` খুলে obsolete rules মুছুন |

## 🔄 Part 3: দৈনিক Workflow

### Session Start (প্রতিবার Claude Code চালু করলে)

**কমান্ড:**
```
"CLAUDE.md, PROGRESS.md, TODO.md পড়ে বলো এখন কোথায় আছি 
 — এখন কোন task টা নেওয়া উচিত?"
```

Claude এই তিনটা পড়ে brief দেবে। তারপর সিদ্ধান্ত নিন।

---

### During Work (কাজ চলাকালীন)

| ধরন | কী বলবেন | Pattern |
|---|---|---|
| নতুন ফিচার | "প্ল্যান দাও, কোড না" | plan-first |
| বাগ ফিক্স | "এই error টা কেন হচ্ছে?" | diagnose-first |
| এডিট | "X ফাইলে Y পরিবর্তন করো" | direct |
| সন্দেহ | "এই approach কি ঠিক আছে?" | review |
| Tracking | "PROGRESS.md তে add করো", "TODO তে tick দাও" | explicit reminder |
| Heavy কাজ | Sub-agent / Task tool | "এই task টা sub-agent কে দাও" |

**Rule:** যেকোনো বড় কাজের আগে plan → approve → execute → verify → record।

---

### Session End (বন্ধ করার আগে)

Claude Code **memory auto-update করে না**, তাই manually:

```
"সেশন শেষ। যা করেছি সেটা PROGRESS.md তে update করো। 
 নতুন কোনো pattern/rule শিখলে CLAUDE.md (/memory) তে save করো।"
```

অথবা hook সেট করে automatic করুন (Part 6 দেখুন)।

### Context বড় হলে

| Command | কী করে |
|---|---|
| `/compact` | পুরো conversation সংক্ষিপ্ত করে — গুরুত্বপূর্ণ অংশ রাখে |
| `/clear` | পুরো context মুছে দেয় (fresh start) |
| `--continue` | পরবর্তী session হিসেবে আগের conversation আবার চালু করে |
| `--resume` | পুরানো saved conversation list দেখায় |

**কখন কোনটা:**
- ৫০+ messages হলে → `/compact`
- সম্পূর্ণ context switch → `/clear`
- আগের কাজ ফেরত → `--continue` বা `--resume`

## 🚀 Part 4: উন্নত Patterns ও Commands

### 4.1 🌐 Browser-Based Testing (ওয়েব প্রজেক্টের জন্য)

Claude Code দুইভাবে browser handle করতে পারে:

| Mode | কীভাবে |
|---|---|
| **`--chrome` flag** দিয়ে launch | Direct browser automation |
| **MCP Playwright** server installed | Programmatic UI testing |

**Chrome mode চালু করতে:**
```bash
claude --chrome
```

তারপর agent browser control করতে পারে — click, type, screenshot।

**Real workflow:**
```
"localhost:3000 open করো, login করো, dashboard এ 
 5টা widget screenshot নাও।"
```

**Sub-agent + Chrome:**
```
"একটা QA task হিসেবে sub-agent launch করো যে ও --chrome mode এ 
 login flow test করবে।"
```

### 4.2 🎯 Goal-Oriented Development (একটা সম্পূর্ণ লক্ষ্য অর্জন)

> ⚠️ `/goal` Claude Code এ built-in slash command না, কিন্তু convention হিসেবে excellent কাজ করে।

**Pattern:**
```
"GOAL: wishlist ফিচার পুরোটা শেষ করতে হবে।

 Criteria:
  - Backend: model + 3টা API endpoint + test pass
  - Frontend: page + add/remove button + real API integration
  - PROGRESS.md আপডেট
  - এর কোনোটাই অসম্পূর্ণ রাখা যাবে না

 sub-tasks ভাগ করো, sequential এ করো, প্রতিটা verify করে 
 পরেরটায় যাও।"
```

**Claude যা করবে:**
- TodoWrite tool দিয়ে sub-tasks track করবে
- sequential এ implement করবে
- প্রতিটা শেষে verify করবে
- criteria পূরণ না হওয়া পর্যন্ত চালিয়ে যাবে

### 4.3 🔁 Iterative Debugging

> ⚠️ `/iteration` pattern — built-in command না, কিন্তু reliable debugging-এর জন্য best practice।

```
"ITERATION: TypeError: Cannot read property 'map' of undefined 
 যেটা HomePage এ হচ্ছে।

 Loop চালাও:
  1. error reproduce করো (browser বা terminal)
  2. root cause খুঁজো
  3. fix apply করো
  4. verify করো (test/browser)
  5. error না গেলে step 1 এ ফেরত যাও, max 8 iteration

 Break: ৮ iteration এ না হলে আমাকে জানাও summary দিয়ে।"
```

**Claude-specific tip:** Bug-fix এ TodoWrite দিয়ে per-iteration track করুন:
```
"প্রতিটা iteration TodoWrite তে entry রাখো — কী try করলে, 
 কী হলো, কেন fail"
```

### 4.4 🧠 Reinforcement Learning (`/memory` দিয়ে)

Claude Code-এ RL mechanism **z-code থেকে আলাদা** — ডিরেক্ট manual save।

**`/memory` কীভাবে ব্যবহার করবেন:**

| পরিস্থিতি | Trigger | Action |
|---|---|---|
| নতুন rule শিখলেন | session-এ error হলে | `/memory` চালিয়ে rule add করুন |
| পুরোনো rule obsolete | weekly review | `/memory` edit করে মুছুন |
| Global preference | যেকোনো সময় | `/memory` add করুন |

**Example: Session-এ ভুল হলে**

```
/memory
```

(Editor খুলবে, ~\.claude/CLAUDE.md)

Add:
```markdown
## Project-specific rule
- Server-side validation সব form input এ — 
  client validation bypassable
```

Save + close → এই rule পরের session থেকে active।

**Discipline:**

| Frequency | Action |
|---|---|
| প্রতিটা session-এ কমপক্ষে ১বার check | `/memory` খুলুন দেখুন কিছু যোগ করার আছে কিনা |
| সপ্তাহে একবার cleanup | পুরো memory পড়ুন, obsolete মুছুন, conflicting merge করুন |
| নতুন project | project-level `/init` চালান |

### 4.5 🔁 Combined Pattern: Goal + Iteration + RL

**সবচেয়ে কার্যকরী কাজের ধরন:**

```
Step 1: GOAL দিন
"GOAL: user profile edit পেজটা পুরোটা শেষ করো।
 Criteria:
  - Backend: PUT /api/users/:id + validation + test pass
  - Frontend: form + validation + success/error state
  - Mobile responsive
  - Browser test pass"

Step 2: TodoWrite auto-tracking
```

## 🤖 Part 6: Auto-Maintenance (Claude Code-এ)

### সমস্যা

Claude Code **tracking files auto-update করে না**। z-code-এর মতো memory rule set করলেই হয় না। আপনাকে বা Claude-কে explicitly:

```
"PROGRESS.md update করো"
"TODO তে tick দাও"
```

বলতে হয় প্রতিটা substantive কাজের পর।

### সমাধান ১: Hook ব্যবহার করুন

**`.claude/settings.json` ফাইল বানান:**

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "bash scripts/track-changes.sh"
          }
        ]
      }
    ]
  }
}
```

**`scripts/track-changes.sh`:**

```bash
#!/bin/bash
# stdin থেকে tool input পড়ি
INPUT=$(cat)
FILE=$(echo "$INPUT" | jq -r '.tool_input.file_path // empty')

if [ -z "$FILE" ]; then
  exit 0
fi

# শুধু কোড ফাইলের জন্য track করি
case "$FILE" in
  *.ts|*.js|*.jsx|*.tsx|*.py|*.html|*.css|*.json)
    DATE=$(date +%Y-%m-%d)
    ENTRY="- [${DATE}] auto: edited ${FILE}"

    # PROGRESS.md তে add (যদি না থাকে)
    if [ -f PROGRESS.md ]; then
      grep -qF "$ENTRY" PROGRESS.md || \
        echo "$ENTRY" >> PROGRESS.md
    fi
    ;;
esac

exit 0
```

**Effect:** প্রতিটা Edit/Write টুল call এর পর shell script automatically PROGRESS.md তে entry add করে।

### সমাধান ২: Strong prompt লিখুন

প্রতিটা substantive কাজের শুরুতে:

```
"আজকের কাজ শেষে PROGRESS.md আপডেট করবে — 
 মনে রাখো এই নোটটা।"
```

অথবা `~/.claude/CLAUDE.md`-তে explicit rule:
```markdown
## সবসময় follow করো
- যেকোনো কাজ শেষে reply দেওয়ার আগে PROGRESS.md update করো
- TODO.md তে finished task এ [x] দাও
```

### সমাধান ৩: TodoWrite tool ব্যবহার করুন

Claude Code-এর TodoWrite (transient task tracker) — পুরো session এ active থাকে:

```
"এই feature ৪-টা sub-task এ ভাগ করো TodoWrite দিয়ে"
```

Claude নিজেই sub-tasks track করবে, শেষে update করবে।

### সমাধান ৪: Periodic Reminder

বড় session-এ প্রতি ১৫-২০ মিনিটে নিজে নিজে বলুন:
```
"এখন পর্যন্ত কী করেছো? PROGRESS update করো।"
```

## 📋 Part 7: Claude Code Best Practices

### Best Practice ১: CLAUDE.md বিভিন্ন level-এ ব্যবহার করুন

```
~/.claude/CLAUDE.md               ← global user preferences
~/projects/my-app/CLAUDE.md      ← project-specific rules
~/projects/my-app/server/CLAUDE.md ← backend-specific rules
```

**Example: Monorepo তে sub-folder CLAUDE.md**

`projects/monorepo/server/CLAUDE.md`:
```markdown
# Server-specific rules
- সব API response { success, data, error } format এ
- Database queries always parameterized
- Logger নামে custom logger ব্যবহার (not console)
```

### Best Practice ২: Sub-Agents for Heavy Tasks

Claude Code-এ Task tool দিয়ে sub-agents spawn করা যায়:

```
"এই PR review এর জন্য একটা code-reviewer agent spawn করো"
```

Use cases:
- বড় refactor
- কোড review
- Test generation
- Documentation writing

### Best Practice ৩: Plan Mode

কঠিন কাজের আগে `Shift + Tab` চেপে plan mode on করুন — Claude শুধু plan দেয়, কোড লেখে না, আপনি approve না করা পর্যন্ত।

```
(Plan mode on)
> Refactor করো authentication middleware
# Claude plan দেয়:
# 1. Read existing middleware
# 2. Identify patterns
# 3. Propose structure
# 4. List of files to change
[Approve / Reject]
# তারপর execute হয়
```

### Best Practice ৪: Permission Modes

`/permissions` বা `claude --permission-mode <mode>`:

| Mode | কী করে |
|---|---|
| `accept-edits` | ফাইল edit auto-accept |
| `bypass-permissions` | সব permission skip |
| `plan` | শুধু plan, কোনো tool use না |
| `default` | প্রতিটা tool এ confirm |

সাধারণত **`accept-edits`** সবচেয়ে productive workflow।
